# 09 — CD tự động (push `main` → build image → máy chủ tự cập nhật)

> Hai web (`fashion_frontend_user`, `fashion_frontend_admin`) đã tự deploy bằng Vercel mỗi lần push — tài liệu này chỉ nói về **backend** trên máy chủ Docker.
> File liên quan: `.github/workflows/ci.yml` (kiểm tra), `.github/workflows/deploy.yml` (CD), `deploy/deploy-remote.sh` (chạy trên máy chủ), `deploy/docker-compose.prod.yml`.

## 1. Luồng chạy

```text
push main ──► CI (lint · ranh giới module · build · test · migration trên DB trống)
                 │ xanh
                 ▼
          Deploy / build: build image bằng GitHub, đẩy ghcr.io/<owner>/<repo>:sha-<12 ký tự> (+ :latest)
                 │
                 ▼  (nếu bật "Required reviewers" ở Environment production: chờ bạn bấm duyệt)
          Deploy / deploy: SSH vào máy chủ
                 1. chép docker-compose.prod.yml + Caddyfile + deploy-remote.sh (KHÔNG đụng .env.production)
                 2. đăng nhập GHCR bằng token của lượt chạy (đăng xuất ngay sau khi kéo xong)
                 3. deploy-remote.sh: sao lưu DB → ghi FITLY_IMAGE mới vào .env.production → docker compose pull
                    → up -d (service `migrate` chạy migration + đồng bộ quyền, rồi api/worker chạy lại) → chờ API "healthy"
                 4. lỗi ⇒ tự quay về image cũ, job báo đỏ
```

CI đỏ ⇒ không build, không deploy. Hai lượt push liên tiếp ⇒ lượt sau chờ lượt trước xong (không bao giờ huỷ giữa chừng lúc đang migrate).

## 2. Cài đặt MỘT LẦN

1. **Đưa workflow lên GitHub.** Push file trong `.github/workflows/` cần token/đăng nhập có quyền **`workflow`** (nếu push bị từ chối với thông báo "workflow scope" thì tạo lại token với quyền đó, hoặc đăng nhập Git bằng GitHub Desktop/Git Credential Manager). Nhớ commit cả `.github/` (hiện `ci.yml` cũng chưa nằm trong git).
2. **Khoá SSH riêng cho CD** (đừng dùng lại khoá cá nhân). Trên máy của bạn:
   ```bash
   ssh-keygen -t ed25519 -N "" -C "github-actions-cd@fitly" -f fitly-cd
   ```
   Thêm **khoá công khai** vào máy chủ (một dòng, có `restrict` để khoá này không mở được cổng/chuyển tiếp):
   ```bash
   printf 'restrict %s\n' "$(cat fitly-cd.pub)" | ssh root@<IP máy chủ> 'cat >> ~/.ssh/authorized_keys'
   ```
   Lấy dòng `known_hosts` của máy chủ: `ssh-keyscan -t ed25519 <IP máy chủ>`.
3. **GitHub → repo backend → Settings → Secrets and variables → Actions**:

   | Loại | Tên | Giá trị |
   |---|---|---|
   | Secret | `DEPLOY_HOST` | IP hoặc tên miền máy chủ |
   | Secret | `DEPLOY_USER` | `root` (hoặc user có quyền chạy Docker) |
   | Secret | `DEPLOY_SSH_KEY` | NỘI DUNG file khoá RIÊNG `fitly-cd` (cả dòng BEGIN/END) |
   | Secret | `DEPLOY_KNOWN_HOSTS` | dòng `ssh-keyscan` ở trên |
   | Variable | `API_PUBLIC_URL` | `https://<SITE_ADDRESS>` (tuỳ chọn — để kiểm sức khoẻ công khai sau deploy) |

   Xong thì xoá file `fitly-cd` (khoá riêng) khỏi máy.
4. **(Khuyến nghị) Bấm duyệt trước khi lên production:** Settings → Environments → `production` → *Required reviewers* → thêm bạn. Lượt deploy sẽ dừng ở bước `deploy` chờ bạn bấm Approve — nên bật vì có migration sửa/xoá dữ liệu.
5. **Lần chạy đầu:** Actions → *Deploy* → *Run workflow* (hoặc push một commit). Lần đầu máy chủ chuyển từ image tự build tại chỗ sang image GHCR; `deploy-remote.sh` tự xử lý (ghi `FITLY_IMAGE` vào `.env.production`).
   Gói image tạo ở trang *Packages* của tài khoản; vì có nhãn `org.opencontainers.image.source` nên gắn với repo và token của workflow đọc/ghi được. Không cần để công khai.

## 3. Dùng hằng ngày

- **Deploy:** push/merge vào `main` và chờ CI xanh. Theo dõi ở tab Actions.
- **Deploy lại một phiên bản cụ thể:** Actions → Deploy → Run workflow → điền `ref` = mã commit (đã từng qua CI).
- **Đổi biến môi trường** (`.env.production` nằm riêng trên máy chủ, KHÔNG nằm trong git): sửa file đó rồi `cd /opt/fitly/eco_backend/deploy && docker compose --env-file .env.production -f docker-compose.prod.yml up -d` (hoặc chạy lại một lượt deploy).
- **Tắt CD tạm thời:** Actions → Deploy → "⋯" → *Disable workflow*.

## 4. Lùi lại khi có sự cố

- **Chỉ lỗi code (không đụng migration):** trên máy chủ
  ```bash
  cd /opt/fitly/eco_backend/deploy
  IMAGE=ghcr.io/<owner>/<repo>:sha-<12 ký tự của bản tốt> ./deploy-remote.sh
  ```
  (danh sách tag ở trang Packages). Script cũng tự quay về image cũ nếu bản mới không khoẻ.
- **Migration đã áp dụng và cần lùi cả dữ liệu:** migration KHÔNG tự lùi. Dùng bản sao lưu tự động `/root/backups/fitly-pre-<giờ>.dump` (giữ 10 bản gần nhất, mỗi lần deploy một bản):
  ```bash
  cd /opt/fitly/eco_backend/deploy
  docker compose --env-file .env.production -f docker-compose.prod.yml stop api worker
  docker compose --env-file .env.production -f docker-compose.prod.yml exec -T db \
    pg_restore -U ecofashion -d ecofashion --clean --if-exists --no-owner < /root/backups/fitly-pre-<giờ>.dump
  IMAGE=<tag bản cũ tương ứng> ./deploy-remote.sh
  ```
  Dữ liệu phát sinh SAU thời điểm sao lưu sẽ mất — chỉ làm khi thật cần.

## 5. Lưu ý

- Mã nguồn không còn được build trên máy chủ (2 GB RAM build chậm) — GitHub build, máy chủ chỉ kéo image. `./deploy.sh` (build tại chỗ) vẫn dùng được khi cần deploy tay: bỏ dòng `FITLY_IMAGE` khỏi `.env.production` để compose quay về image `fitly-backend:prod`.
- Khoá CD ở dạng `restrict` vẫn chạy được lệnh trên máy chủ ⇒ coi nó như mật khẩu root của dự án: chỉ để trong GitHub Secrets, đừng dán ở nơi khác. Muốn chặt hơn: tạo user riêng thuộc nhóm `docker` và để `DEPLOY_USER` là user đó.
- Mỗi lần deploy ghi sao lưu DB vào `/root/backups`; kiểm tra dung lượng đĩa định kỳ (`df -h`).
- Biến `FITLY_IMAGE` do script quản lý — đừng sửa tay trừ khi biết mình đang làm gì.
